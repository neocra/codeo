# Codeo architecture

## Components

```
┌──────────────────────┐      ┌──────────────────────┐
│  Codeo Desktop       │      │  Codeo Remote        │
│  Electron + React    │      │  Expo / React Native │
│  renderer ⇄ preload  │      │                      │
│  ⇄ main (ws client)  │      │  ws client           │
└──────────┬───────────┘      └──────────┬───────────┘
           │ loopback WebSocket, token   │ TLS WebSocket, device token + scopes
           ▼                             ▼
┌──────────────────────┐      ┌──────────────────────┐
│  Codeo Runtime       │◄─────┤  Remote Gateway      │
│  Node process        │ out- │  Fastify + ws relay  │
│  sessions · approvals│ bound│  pairing · tokens    │
│  tasks · workspaces  │      │  audit · revocation  │
│  event log · SQLite  │      └──────────────────────┘
└──────────┬───────────┘
           │ official SDKs / git CLI
           ▼
   Claude Code · Codex · Git worktrees
```

- **Clients never execute work.** Desktop renderer and mobile only send typed commands and render
  typed events. Electron's renderer runs sandboxed with context isolation; the preload exposes a
  single `window.codeo` bridge (`apps/desktop/src/shared/bridge-types.ts`).
- **The Runtime owns execution** (`apps/runtime`). It is a plain Node program: Electron spawns it with
  `ELECTRON_RUN_AS_NODE=1` so packaged builds need no separate Node, but it also runs by hand
  (`pnpm --filter @codeo/runtime start`) and keeps working while the window is closed. Quitting the
  desktop app stops the runtime it started; an externally started runtime is only attached to.
- **The Gateway relays** (`apps/gateway`). Runtimes connect outbound; paired devices get short-lived
  tokens with scopes; every command is authorized before it is forwarded.

## Protocol (`packages/contracts`)

One WebSocket, JSON frames validated with zod on both sides:

- `hello` (token, client kind, `afterSeq`) → `welcome` (runtime info, `lastSeq`, granted scopes) and a
  replay of persisted events with `seq > afterSeq`.
- `request {id, command, params}` → `response {id, ok, result | error{code}}`. Every command declares a
  scope (`read`, `session:write`, `approval:decide`, `workspace:admin`); params and results are parsed.
- `event {seq, event}` — a discriminated union (`SessionEntryAppended`, `ApprovalRequested`, …) with
  global monotonic sequence numbers persisted in the `events` table, so reconnecting clients resume
  from where they stopped instead of reloading state.

## Domain (`packages/domain`)

Entities are zod schemas (Workspace, Repository, Ticket, Task, Subtask, AgentSession, SessionEntry,
ApprovalRequest, Worktree, PullRequest, CICheck, Plugin, RemoteDevice, Machine) with explicit state
machines (`state-machines.ts`): invalid transitions throw, expired approvals cannot be accepted,
completed tasks cannot silently run again. Nothing in the domain depends on Jira, GitHub or SDK formats.

## Providers (`packages/agent-providers`)

`AgentProvider` = `detect()` + `startSession()`. Adapters translate official SDK streams into one
`ProviderEvent` union (`text_delta`, `tool_call_started`, `turn_completed`, …):

- **Claude Code** — `@anthropic-ai/claude-agent-sdk` `query()` in streaming-input mode (so `interrupt()`
  and follow-up turns work in one process), `includePartialMessages` for live text, `canUseTool` →
  Codeo approval requests, `resume` with the stored `session_id`. Detection runs the bundled native
  CLI (`--version`, `auth status --json`).
- **Codex** — `@openai/codex-sdk` `startThread()/resumeThread()` + `runStreamed()`; `codex exec` is
  non-interactive so the adapter reports `permissionRequests: false` and relies on Codex's sandbox.
  Detection runs the bundled CLI (`--version`, `login status`).

## Runtime services (`apps/runtime/src/services`)

- `SessionService` — one live provider handle per session; persists every transcript entry
  (`session_entries`) and publishes events; coalesces streaming deltas (≈60 ms).
- `ApprovalService` — persists a pending request, waits for exactly one decision (desktop or mobile),
  expires after 15 min, cancels with the session, and expires anything left pending after a restart.
- `TaskService` — phase 3 scope: task → one subtask → one session; task status follows the session.
- `WorkspaceService` — inspects repositories with `@codeo/git` (no shell, argument arrays).
- `EventBus` — append-only persisted log with serialized writes.

## Persistence (`packages/database`)

SQLite through `@libsql/client` (N-API, so it loads inside Electron's Node without rebuilds) and Drizzle.
Migrations are generated by drizzle-kit and applied at startup. Data lives in `~/.codeo/codeo.db`.

## Security model

See `docs/security/`. Short version: sandboxed renderer and minimal IPC; loopback runtime with a
per-launch token; approvals are explicit, single-use, scoped to one tool call and expire; credentials
are never logged (`redactSecrets` on every log line and outgoing frame); git runs with
`GIT_TERMINAL_PROMPT=0` and structured args; worktrees with uncommitted changes are never removed
without an explicit force.
